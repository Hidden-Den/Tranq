# Правила и регламент разработки проекта Tranq

## 0. Видение продукта и контроль отклонений

**Tranq — лёгкая диктовка для macOS.** Нажал клавишу, сказал, в активное поле вставился чистый, лаконичный текст.

- **Русская речь** с латинскими терминами. Английские диктовки не цель.
- **Главная ценность — очистка**: убрать паразиты, самоисправления и повторы мыслей, сохранив слова и факты говорящего.
- **Тон под приложение и режим промпта** — только по выбору пользователя.
- **Три способа обработки**: локально без сети, внешний API, корпоративный шлюз за VPN.
- **Лёгкость важнее количества функций**: всё, что не служит диктовке, убирается.

Подробные решения: `docs/superpowers/specs/2026-11-17-dictation-focus-design.md`.

**Правило для агентов.** Если запрос пользователя уводит от этого видения — новая функция не про диктовку, усложнение интерфейса, возврат убранного, работа вне раздела «Порядок работ» спеки — до начала работы прямо скажи об этом одной-двумя фразами: в чём отклонение и что сейчас ближе к цели. Решение остаётся за пользователем: если он подтверждает, делай. Не молчи и не отказывай.

## 1. Регламент версионирования проекта

В проекте Tranq строго соблюдается следующая конвенция версионирования:

1. **Глобальные изменения и новые фичи (Feature Releases)**:
   - Формат версии: `X.Y` или тег `vX.Y.0`, например `3.1`, `3.2`, `3.3`.
   - Применяется при добавлении новой ключевой функциональности, крупных подсистем или глобальных пользовательских возможностей, например интеграция со строкой статуса macOS, режим скрытия приложения в Dock, поддержка новых системных модификаторов.
   - Старшая цифра растёт только при смене имени, bundle ID или несовместимом изменении данных. Текущая линия `3.x`: переименование в Tranq.

2. **Доработки, патчи и минорные улучшения (Patch / Maintenance Releases)**:
   - Формат версии: `X.Y.Z` или тег `vX.Y.Z`, например `3.1.1`, `3.1.2`.
   - Применяется при исправлении ошибок, полировке UI/UX, оптимизациях производительности, улучшении доступности (VoiceOver), обновлении локализаций и точечных доработках существующих функций.

3. **Синхронизация версии**:
   - При выпуске релиза значение `MARKETING_VERSION` обновляется в `Tranq.xcodeproj/project.pbxproj`.
   - Git-тег релиза создается в формате `vX.Y.0` для фичи или `vX.Y.Z` для патча.
   - В релиз на GitHub прикрепляется свежесобранный `.dmg` образ (`build/Tranq.dmg`).

## 2. Принципы дизайна интерфейса (Minimal Linear & Notion Aesthetic)

- **Строго без круглых скобок в UI**: избегать `(...)`, `[...]` и `{...}` в пользовательском тексте, заголовках и подзаголовках, если смысл можно передать без них.
- **Лаконичный микрокопирайтинг**: метки — 1–2 слова, подзаголовки — строго менее 8 слов, никаких обучающих абзацев на экране.
- **Нулевая избыточность**: никаких дублирующихся кнопок или повторяющихся действий в одном экране.

## 2.1. Бренд

- Имя только `Tranq`, латиницей. Старое имя в репозитории не допускается, проверка `scripts/check-brand.sh` идёт в CI.
- Весь текст интерфейса набирается Inter через `Font.ui`. Knewave только для названия и буквы Q через `Font.brand`.
- Иконка `Tranq/AppIcon.icon`, контур Q лежит в `Brand/q.svg`, получен из Knewave скриптом `Brand/extract-q.py`.
- Акцентного цвета нет: монохром и семантические цвета состояний.

## 3. Регламент GitHub и Cubic AI

- Все ветки, PR и релизы публикуются исключительно на **GitHub**.
- **Категорический запрет на автоматическое создание PR**: Pull Request создается **ТОЛЬКО при прямом и явном указании пользователя** (например: «создай PR», «отправь в Cubic на ревью», «сделай пулл-реквест»). Никаких автоматических PR после обычных коммитов, пушей или релизов!
- При явном запросе на PR он создается только один раз в состоянии Feature-Ready после прохождения всех локальных тестов.
- Все замечания Cubic AI устраняются коммитами в ветку того же PR без его пересоздания.
