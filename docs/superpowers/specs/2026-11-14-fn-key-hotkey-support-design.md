# Дизайн: Поддержка одиночной клавиши Fn (Globe) для диктовки в Golosok

**Дата:** 2026-11-14  
**Статус:** На утверждении  
**Объем:** Небольшое изменение (Small change)

---

## 1. Цель и контекст (Intent & The Why)
В macOS на современных клавиатурах Apple (Magic Keyboard и встроенные клавиатуры MacBook) клавиша `Fn` совмещена с иконкой глобуса (Globe 🌐) и микрофона. Пользователи привыкли использовать ее как естественную кнопку для голосового ввода одной клавишей.
В текущей версии Golosok поддерживаются только комбинации клавиш (модификатор + символьная клавиша через Carbon `RegisterEventHotKey`).
**Цель:** реализовать возможность назначения одиночной клавиши `Fn` для управления диктовкой в двух режимах (рация / переключатель).

---

## 2. Цели, не-цели и анти-цели (Goals, Non-Goals, Anti-Goals)

### Цели (Goals)
- Поддержка одиночной клавиши `Fn` (код клавиши 63, событие `flagsChanged`) в качестве триггера диктовки.
- Полная поддержка обоих режимов работы с `Fn`:
  - **Режим рации (Push-to-Talk):** зажатие `Fn` начинает запись, отпускание `Fn` останавливает запись и вставляет текст.
  - **Режим диктовки (Toggle):** первое нажатие `Fn` начинает запись, второе нажатие останавливает запись и вставляет текст.
- Интерактивный захват: при нажатии кнопки «Изменить» в настройках нажатие `Fn` корректно определяется и сохраняется.
- Подавление системного конфликта macOS: когда `Fn` назначен горячей клавишей диктовки, системные действия macOS на эту клавишу (например, вызов панели эмодзи или смена раскладки) не должны мешать процессу диктовки.
- Сохранение полной обратной совместимости с существующими комбинациями клавиш (например, `⌥ + Space`).

### Не-цели (Non-Goals)
- Назначение немодификаторных одиночных символьных клавиш (буквы, цифры) без модификаторов в качестве глобального хоткея.
- Замена существующих аудиомоделей или логики вставки текста.

### Анти-цели (Anti-Goals)
- Не допустить зависания или падения UI потока при создании `CGEventTap`.
- Не сломать работу стандартного хоткея `⌥ + Space` для пользователей, предпочитающих комбинации.

---

## 3. Ограничения (Constraints)
- Carbon API (`RegisterEventHotKey`) принципиально не поддерживает одиночный `Fn` и события модификаторов (`flagsChanged`).
- Для перехвата `Fn` на уровне системы требуется `CGEventTap`, который опирается на права Accessibility (`AXIsProcessTrusted`). У Golosok это разрешение уже является обязательным базовым требованием.
- UI должен строго соответствовать минималистичному дизайну Linear/Notion (отсутствие скобок в тексте интерфейса, лаконичный микротекст).

---

## 4. Рассмотренные подходы (Approaches)

1. **Вариант 1 (Выбранный): Гибридный обработчик (Carbon для комбинаций + `CGEventTap` для `Fn`)**
   - Если активна стандартная комбинация клавиш — используется энергоэффективный `RegisterEventHotKey`.
   - Если выбрана клавиша `Fn` — активируется `CGEventTap` с фильтром по `CGEventType.flagsChanged` и коду 63.
   - *Плюсы:* Надежность, точный учет key-down/key-up, возможность поглощения события для предотвращения системных конфликтов macOS (всплывающие эмодзи/язык), отсутствие оверхенда для обычных комбинаций.

2. **Вариант 2: Пассивный `NSEvent.addGlobalMonitorForEvents`**
   - *Минусы:* Не может блокировать системное действие macOS на клавишу Globe, что приводит к параллельному открытию окна эмодзи или переключению языка при диктовке.

3. **Вариант 3: Полная замена Carbon на `CGEventTap` для всех клавиш**
   - *Минусы:* Избыточное усложнение для стандартных сочетаний клавиш.

## 5. Архитектура и реализация (Technical Specification)

### 5.1. Хранение настроек (`HotKeySettings` и `UserDefaults`)
- Используется модель `HotKeyTrigger`: `.combination(keyCode, modifiers)` или `.singleModifier(SingleModifierKey)`.
- В `UserDefaults`:
  - `hotkey.type`: `"combo"` или `"modifier"`
  - При `type == "modifier"`: `hotkey.modifierKeyCode` (например, 63 для Fn, 61 для Right Option)
  - При `type == "combo"`: сохраняются `hotkey.keyCode` и `hotkey.modifiers`
- Обратная совместимость: если `hotkey.type` не задан, по умолчанию используется `combo` с `keyCode` (по умолчанию 49) и `modifiers` (по умолчанию optionKey).
- Метод `displayName()` возвращает локализованное название клавиши или комбинации (например, `"Fn"`, `"Правый ⌥"`, `"⌥ + Space"`).

### 5.2. Детектирование клавиши в `HotKeySettings.beginCapture()`
- Монитор захвата расширяется: помимо `.keyDown`, слушается `.flagsChanged`.
- При фиксации нажатия клавиши с `keyCode == 63` или флагом `.function` (без сопутствующих символьных клавиш) захват завершается установкой `isFnKey = true`.

### 5.3. Обработка событий в `NativeHotKeyManager`
- При регистрации хоткея:
  - Если `isFnKey == false`: регистрируется Carbon `RegisterEventHotKey` (как сейчас).
  - Если `isFnKey == true`: создается `CGEventTap` для события `flagsChanged`.
- В коллбэке `CGEventTap`:
  - Проверяется `keyCode == 63` (клавиша Fn / Globe).
  - Проверяется состояние флага `NSEvent.ModifierFlags.function` (нажата или отпущена):
    - **Флаг установлен (Key Down):**
      - Если режим `pushToTalk` — запуск записи (`onHotKeyPressed`).
      - Если режим `toggle` — переключение записи (`onHotKeyPressed`).
    - **Флаг снят (Key Up):**
      - Если режим `pushToTalk` — завершение записи (`onHotKeyReleased`).
  - Возвращается `nil` (поглощение события), чтобы система не запускала дефолтные действия на Globe во время использования Golosok.

### 5.4. Интерфейс (`SettingsView`)
- В блоке «Управление»:
  - Бейдж показывает `Fn`, если назначена клавиша Fn, либо текущую комбинацию (например, `⌥ + Space`).
  - Добавляется быстрый переключатель / пресет (`⌥ + Space` или `Fn`), а также кнопка «Изменить» для захвата с клавиатуры.
  - Тексты строго без скобок в соответствии с правилами минималистичного UI.
